server.ts 
import { serve, Router } from '@symmetra/http';

const app = new Router();

// Runs entirely on GPU — 1 CUDA thread per request
app.get('/ping', (ctx) => {
  ctx.json({ message: 'pong', gpu: true });
});

// .map() → __global__ kernel, 1 thread per element
app.post('/transform', async (ctx) => {
  const data   = await ctx.body<Float32Array>();
  const result = data.map(x => x * x + Math.sin(x));
  ctx.json(result);
});

serve(app, { port: 8080 });

Everything on GPU.

⚡

TypeScript → CUDA

Your handlers compile to __device__ functions. .map() becomes a __global__ kernel. Math functions remap to CUDA intrinsics. No JavaScript engine involved.

🔥

GPU-native HTTP

HTTP parsing, URL routing, JSON serialization, and response caching all run in VRAM. CPU handles one thing: TCP accept/recv/send. That's it.

📦

VRAM key-value

@symmetra/kv stores everything in VRAM. No Redis. No DRAM round-trip. LRU eviction with configurable TTL. Sub-microsecond reads.

🔒

Protected engine

The Symmetra engine binary is proprietary and signed. CUDA PTX is embedded as an opaque byte array. Your users download a binary, not source code.

🧬

136 TM engines

APEX (16 GH/s), RAYK (8.14 GH/s), PHI_RAYK, OMEGA (auto-select). Turing machine-based fingerprinting for routing, caching, and auth.

🛠

No config

One binary. No tsconfig.json to configure, no bundler to set up. Run symmetra ./server.ts and you're live.
