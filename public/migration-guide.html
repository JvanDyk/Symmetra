Engine Naming Migration Guide

Learn how to update your code to use the new standardized Turing machine engine names

Overview

Symmetra has standardized engine naming to be more user-friendly and Docker-compatible. All internal platform references (GPU/CPU/Apple/hardware specifics) have been removed from public-facing names.

New Format: symmetra:tm-{engine-name}:{version}
Example: symmetra:tm-rayk-ultra:1.0.0

How to Update Your Code

Configuration Files

Update your symmetra.config.yml or environment variables:

# Old format (still supported with warnings) engine: RAYK_ULTRA_64_MULTI # New format (recommended) engine: symmetra:tm-rayk-ultra:1.0.0 # Multiple engines engines: - symmetra:tm-rayk-ultra:1.0.0 - symmetra:tm-bitwise-rule60:1.0.0

CLI Commands

# Old symmetra install RAYK_ULTRA_64_MULTI # New symmetra install tm-rayk-ultra symmetra install symmetra:tm-rayk-ultra:1.0.0

Docker

# Old approach docker run -e ENGINE=RAYK_ULTRA_64_MULTI symmetra # New approach docker pull symmetra:tm-rayk-ultra:1.0.0 docker run symmetra:tm-rayk-ultra:1.0.0

Environment Variables

# Old export SYMMETRA_ENGINE=RAYK_ULTRA_64_MULTI # New export SYMMETRA_ENGINE=symmetra:tm-rayk-ultra:1.0.0 # or shorter form export SYMMETRA_ENGINE=tm-rayk-ultra

Backward Compatibility

Good News: Old engine names still work internally. Your existing code will continue to run, but you'll see deprecation warnings encouraging you to migrate to the new naming convention.

Timeline

  • Now (v1.0.0): New naming available, old names supported with warnings
  • v1.2.0 (Q3 2026): Deprecation period begins - warnings increase
  • v2.0.0 (Q4 2026): Old names may not be supported

We recommend migrating at your convenience, but there's no rush. The new naming is more user-friendly but functionally equivalent.

FAQ

Can I use both old and new names?

Yes, temporarily. Old names still work but display deprecation warnings. We recommend migrating to the new format when convenient.

Do I need to update my version pinning?

No. All engines start at version 1.0.0. You can pin to specific versions using the new format: symmetra:tm-rayk-ultra:1.0.0

What about custom engines?

Custom engines follow the same naming convention: symmetra:tm-{your-name}:{version}

Where do I find the complete mapping?

See the Engines Catalog for all available engines and their new identifiers. The full technical mapping is in ENGINE_NAMING_STANDARD.md

Why the change?

The new naming convention is:

  • User-friendly: No confusing platform abbreviations (GPU/CPU/Apple)
  • Docker-compatible: Works with containerization tools
  • Semantic: Includes version information
  • Consistent: All engines follow the same format

Migration Examples

Example 1: Simple Engine Swap

// Old code const server = await symmetra.createServer({ engine: 'RAYK_ULTRA_64_MULTI' }); // New code const server = await symmetra.createServer({ engine: 'symmetra:tm-rayk-ultra:1.0.0' });

Example 2: Configuration File

# symmetra.config.yml (old) server: engine: BITWISE_RULE60_GPU workers: 4 # symmetra.config.yml (new) server: engine: symmetra:tm-bitwise-rule60:1.0.0 workers: 4

Example 3: Docker Compose

# docker-compose.yml (old) services: api: image: symmetra:latest environment: - SYMMETRA_ENGINE=RAYK_ULTRA_64_MULTI # docker-compose.yml (new) services: api: image: symmetra:tm-rayk-ultra:1.0.0 # or use the base image with env var image: symmetra:latest environment: - SYMMETRA_ENGINE=symmetra:tm-rayk-ultra:1.0.0
