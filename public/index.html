Thousands of threads. Zero coordination overhead.

Symmetra layers three levels of parallelism simultaneously. You write normal TypeScript — the runtime assembles the thread hierarchy automatically.

One thread per CPU core accepts connections and copies request data to pinned VRAM via DMA. CPU cores are never idle.

What you get

Everything on GPU.

⚡

TypeScript → CUDA, directly

Your route handlers become __device__ functions. .map() becomes a __global__ kernel. Math.sin() becomes sinf() — a CUDA hardware intrinsic. Zero abstraction penalty.

🔥

GPU-native HTTP server

HTTP parsing, URL routing, JSON serialization, and response construction all happen in VRAM. The CPU does exactly three things: accept(fd), recv(buf), send(buf). Nothing else.

📦

VRAM key-value store

@symmetra/kv keeps your cache in VRAM — no Redis, no DRAM round-trip, no serialization. Sub-microsecond reads. LRU eviction. Configurable TTL. Your hot data never leaves the GPU.

🧬

GPU fingerprinting

Built-in cellular-automaton hashing runs entirely on-chip — use it for session tokens, cache keys, routing decisions, and auth. No CPU round-trip. No memory bandwidth wasted.

🛠

Zero configuration

No tsconfig.json. No bundler. No build step. No environment to manage. sym ./server.ts and you're live — the compiler, JIT, and runtime are all in one 3MB binary.

🔒

Built-in protection

The Symmetra engine is proprietary and hardened. CUDA kernels ship AES-256 encrypted. Strings are XOR-obfuscated at compile time. Anti-debug runs continuously. Your users get a binary, not source.

🧵

Warp-parallel scheduling

Route matching uses __ballot_sync — a single GPU instruction that compares 32 routes simultaneously across one warp. Kernel block sizes are auto-tuned by cudaOccupancyMaxPotentialBlockSize to maximise SM utilisation for each specific handler.

🌊

32-stream concurrent dispatch

A pre-created pool of 32 CUDA streams means 32 requests process simultaneously, fully independently. Each stream dispatches its own kernel pipeline — HTTP parse, route, handler, serialise — without blocking any other stream.

🗑

VRAM arena GC — O(1) cleanup

Every request allocation (headers, body, output buffer, intermediate arrays) comes from a 4 MB VRAM slab with a bump-pointer. When the response is sent, the entire request's memory is freed in one instruction — a single integer reset. No GC pause. No fragmentation. No per-object tracking.

⚙️

Multi-core I/O thread pool

TCP accept() and recv() run on a CPU thread pool — one worker per core. Workers copy data into pinned memory via DMA and feed GPU streams continuously. CPU cores and GPU SMs stay saturated simultaneously.

FAQ

Common questions.

Do I need to know CUDA or C++ to use Symmetra?

No. You write TypeScript exactly as you would for Node.js. The Symmetra compiler handles everything — type stripping, AST walking, CUDA C++ codegen, JIT compilation. You never touch a .cu file.

What GPU do I need?

Any NVIDIA GPU with compute capability sm_75 or higher: RTX 2070, 2080, 3060, 3070, 3080, 3090, 4070, 4080, 4090, 5070, 5080, 5090, and most Quadro/datacenter cards from 2019 onward. AMD and Apple GPUs are not supported — Symmetra requires CUDA.

Is Symmetra open source?

The SDK (@symmetra/http, @symmetra/kv, @symmetra/core) is MIT-licensed and open source. The engine binary (sym) is proprietary — you get the compiled binary, not the engine source. This protects the compiler and runtime from being reverse-engineered or forked.

How does error reporting work for developers?

Compilation errors show your .ts filename and the exact line. Use --verbose to inspect the generated CUDA C++ and the NVRTC compile log. The engine itself is protected, but your development experience is not compromised.

Can I use npm packages in my Symmetra server?

Only @symmetra/* packages can run on GPU. Standard npm packages that rely on Node.js built-ins (fs, net, crypto, etc.) cannot run on GPU and will throw a compile-time error. This is by design — GPU code must be deterministic and side-effect-free.

What's the performance on a consumer RTX 3060?

An RTX 3060 (sm_86, 3584 CUDA cores) handles roughly 600k–800k simple JSON requests/sec — still 3–4× faster than Node.js + Fastify on a high-end CPU. Performance scales linearly with GPU core count and memory bandwidth.
