Input Contract

Accepts any TypeScript that doesn't rely on workers, dynamic eval, native add-ons, or file-system blocking APIs. All types are erased before parsing — generics, as casts, and interface declarations produce zero runtime output.

What Codegen injects

A ~1,500-line CUDA C++ prelude defining SymmCtx, Map, Set, URL, TextEncoder, RegExp (NFA engine), all String.* helpers, Math.* remaps, Promise stubs, and the warp-aligned symm_dispatch_batch kernel entry point.

PTX is ephemeral

After cuModuleLoadData the PTX string is immediately zeroed in heap memory. The driver has already JIT-compiled it into a native cubin inside the GPU. Dumping process memory after startup reveals no PTX.

⚡ Hardware
GPU — Streaming Multiprocessors · Warps · VRAM
Each SM runs up to 32 warps simultaneously. A warp is 32 threads executing the same instruction. The batch kernel launches exactly 1 block of 256 threads (8 warps) — all on the same route handler — ensuring zero branch divergence at the dispatch switch. VRAM access is coalesced when adjacent threads read/write adjacent addresses.

Section 3

Request Lifecycle (Batch Mode)

A single HTTP request travels through 11 phases across CPU, DMA bus, and GPU. The grey zone (phases 5–8) is where user TypeScript executes — every other phase is C++ infrastructure.

1

TCP Accept

IO thread wins ::accept() from the shared listen socket. No CUDA context touched yet.

~1 µs
2

HTTP Parse

CPU reads headers + body (recvAll). Parses method, path, headers, Content-Length body boundary.

~5 µs
3

Route Match

CPU scans the RouteReg table. Resolves param segments (/users/:id). Resolves to a routeId integer.

<1 µs
4

BatchScheduler Submit

Request is placed in the per-route queue as a BatchRequest. The accept thread immediately returns to ::accept(). fd ownership transfers to the BatchRequest.

<1 µs
5

Batch Fill Window

Scheduler waits for 255 more same-route requests or the 5 ms fill deadline. If a batch of 256 arrives first, it fires immediately. Remaining slots are padded to a warp boundary.

0–5 ms
6

H2D Upload (DMA)

BatchContext::uploadBatch copies request bodies, paths, methods, and the d_active bitmask into VRAM via 8 async cuMemcpyHtoDAsync calls on the acquired stream.

~30 µs
7

Kernel Launch

cuLaunchKernel(symm_dispatch_batch, 1,1,1, padded,1,1, …). One block, up to 256 threads. All threads in the block execute the same route case — zero warp divergence at the switch(route_id).

~2 µs overhead
8

User Handler Executes on GPU

Your TypeScript (compiled to CUDA C++) runs. Reads body, writes JSON to resp_buf, sets resp_len and resp_status. __syncwarp() ensures all threads in each warp finish before the block exits.

10–500 µs
9

D2H Download (DMA)

BatchContext::downloadResults: async copy of d_resp_lens and d_statuses (small), then sync, then per-slot body copy.

~30 µs
10

HTTP Response Build

buildResponse() assembles the HTTP/1.1 status line + headers + body string for each slot in the batch.

~1 µs/slot
11

TCP Send + Close

sendBatchResponses() calls ::send(fd, …) and CLOSE_SOCKET(fd) for each slot. Stream returned to pool.

~10 µs/slot

Tier-3: External I/O (split-kernel CPS)

When a handler calls @symmetra/net or @symmetra/db, it cannot block — the GPU has no scheduler that could yield. Instead:

  1. Kernel A writes the I/O request to a VRAM I/O queue and sets ctx.io_stage = N, then returns.
  2. CPU I/O proxy thread picks up the request, performs the HTTP call or DB query (~ms), writes the result back to VRAM.
  3. Kernel B (continuation) is launched on the same stream with io_stage = N, resumes execution after the I/O point.

Status: architecture designed, VRAM I/O queue format defined in SymmCtx.io_stage; full proxy implementation pending for @symmetra/net and @symmetra/db.

Why the SIMT model fits HTTP servers

HTTP servers are embarrassingly parallel — each request is independent. SIMT (Single Instruction, Multiple Threads) hardware runs 32 identical threads in lock-step per warp. If all 32 threads execute the same route handler, there is zero branch divergence — full warp throughput.

This is why BatchScheduler groups by routeId: a batch where all threads call GET /products is as fast as a single thread; a mixed batch where half call GET /products and half POST /orders would serialize both paths.

The GPU is also the only commodity hardware that can sustain ~10 TB/s VRAM bandwidth — letting per-request KV lookups, JSON parsing, and response serialization happen in tens of microseconds rather than milliseconds.
